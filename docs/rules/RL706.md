# RL706 `aria-prohibited-attr`

aria-label and aria-labelledby must not be used on elements that cannot be named.

## WCAG

- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

WAI-ARIA forbids names on some roles: `generic` (`<div>`, `<span>`), `paragraph`, `presentation`, `code`, `strong` and a few more. Screen readers ignore an `aria-label` there, so a star rating written as `<span aria-label="4 out of 5 stars">★★★★☆</span>` is read as five star symbols, or not at all.

## What ramplint reports

- `aria-label` or `aria-labelledby` on `<div>`, `<span>`, `<p>`, `<b>`, `<i>`, `<em>`, `<strong>`, `<code>`, `<small>`, `<sub>`, `<sup>`, `<del>`, `<ins>` and similar elements without a role.
- The same on elements with `role="presentation"`, `role="none"`, `role="generic"`, `role="paragraph"` and the other roles that prohibit a name.

## Examples

Problems:

```django
{# ✗ #} <span class="stars" aria-label="4 out of 5 stars">★★★★☆</span>
{# ✗ #} <div aria-label="Shipping options">{% include "shipping.html" %}</div>
```

Fixed:

```django
{# ✓ #} <span class="stars" role="img" aria-label="4 out of 5 stars">★★★★☆</span>
{# ✓ #} <div role="group" aria-label="Shipping options">{% include "shipping.html" %}</div>
```

## Not reported

- Elements with a role that can be named (`img`, `group`, `region`, `button`, ...), and landmarks such as `<nav>` and `<section>`.
- Focusable elements (`tabindex`) without a role: they are widgets missing their role.
- Roles built by the template.

## Suppressing

```django
{# ramplint: ignore RL706 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL706 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL706"]
```
