# RL303 `duplicate-id`

id attributes must be unique within a template.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)
- Also 4.1.1 Parsing in WCAG 2.0 and 2.1.

## Why it matters

`<label for>`, `aria-labelledby`, `aria-describedby` and skip links all point at an `id`. When two elements share one, browsers pick the first and the reference silently breaks for the other.

## What ramplint reports

- The same static `id` used more than once in a template. The problem is reported on each repeat and points to the first use.

## Examples

Problems:

```django
{# ✗ #} <p id="help">Use your work email.</p>
{# ✗ #} <p id="help">Forgot your password?</p>
```

Fixed:

```django
{# ✓ #} {% if user.is_authenticated %}<p id="greeting">Welcome back</p>{% else %}<p id="greeting">Hello, guest</p>{% endif %}
{# ✓ #} <p id="row-{{ forloop.counter }}">…</p>
```

## Not reported

- The same id in mutually exclusive branches: `{% if %}` / `{% elif %}` / `{% else %}`, `{% for %}` / `{% empty %}`.
- Ids built from variables.
- Content of `<template>` elements.

## Suppressing

```django
{# ramplint: ignore RL303 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL303 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL303"]
```
