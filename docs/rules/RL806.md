# RL806 `dialog-focus`

Modal dialogs must take focus and keep it; Tab must never get stuck.

## WCAG

- [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) (level A)
- [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) (level A)

## Why it matters

When a modal dialog opens, keyboard and screen reader users must land in it; otherwise they keep tabbing through the page behind it, which they cannot see or use. And Tab must never get stuck: a keyboard trap leaves a keyboard user unable to reach the rest of the page.

## What ramplint reports

This rule needs a rendered page: it runs in the browser scan
(`ramplint http://localhost:8000/` or `ramplint --runserver`) and is skipped
when ramplint lints templates.

- A modal dialog (`<dialog>` opened with `showModal()`, or `role="dialog"` with `aria-modal="true"`) that opens without moving focus into itself.
- An open modal dialog that lets Tab move focus to the page behind it.
- A keyboard trap: Tab keeps moving between the same few elements and never reaches the rest of the page.

## Examples

Problems:

```html
<div role="dialog" aria-modal="true" aria-label="Help">...</div>
<script>openButton.onclick = () => { help.hidden = false; };</script>
```

Fixed:

```html
<dialog id="help" aria-label="Help">...</dialog>
<script>openButton.onclick = () => help.showModal();</script>
```

## Not reported

- Non-modal dialogs and popovers (focus may stay on the trigger).
- Focus moving to the browser's own toolbar after the last element of a dialog.

## Suppressing

Put an HTML comment (it stays in the rendered page) on the line with the
element or the line above it:

```html
<!-- ramplint: ignore RL806 -->
```

or disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL806"]
```
