# RL101 `img-alt`

Images must have an alt attribute.

## WCAG

- [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) (level A)

## Why it matters

Screen readers announce an image by its `alt` text. Without the attribute they fall back to the file name ("logo underscore final dot png") or skip the image entirely, so the information it carries is lost. An empty `alt=""` is the correct way to mark an image as decorative.

## What ramplint reports

- `<img>` without an `alt` attribute (`alt=""` is allowed for decorative images).
- `<input type="image">` without a non-empty `alt`: it is a button and needs a name.
- `<area href>` in an image map without a non-empty `alt`.

## Examples

Problems:

```django
{# ✗ #} <img src="{% static 'img/logo.svg' %}">
{# ✗ #} <input type="image" src="{% static 'img/search.png' %}">
```

Fixed:

```django
{# ✓ #} <img src="{% static 'img/logo.svg' %}" alt="Shoply">
{# ✓ #} <img src="{% static 'img/divider.png' %}" alt="">
{# ✓ #} <img src="{{ product.image.url }}" alt="{{ product.name }}">
```

## Not reported

- `aria-label` or `aria-labelledby` on the image.
- Attributes rendered at runtime, e.g. `<img {{ attrs }}>`.

## Suppressing

```django
{# ramplint: ignore RL101 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL101 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL101"]
```
