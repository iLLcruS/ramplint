# RL701 `aria-role`

role values must be valid, non-abstract WAI-ARIA roles.

## WCAG

- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

Browsers ignore a `role` they do not recognise. A typo such as `role="dailog"` silently turns a dialog into a plain `<div>`, so screen readers announce nothing special. Abstract roles like `widget` or `landmark` only exist to organise the specification and do nothing in markup.

## What ramplint reports

- `role` values that are not WAI-ARIA, Graphics ARIA or DPUB-ARIA roles, with a "did you mean" suggestion.
- Abstract roles (`command`, `composite`, `input`, `landmark`, `range`, `roletype`, `section`, `sectionhead`, `select`, `structure`, `widget`, `window`).

## Examples

Problems:

```django
{# ✗ #} <div role="dailog" aria-modal="true">…</div>
{# ✗ #} <div role="widget">…</div>
```

Fixed:

```django
{# ✓ #} <div role="dialog" aria-modal="true" aria-label="Filters">…</div>
{# ✓ #} <div role="switch checkbox" aria-checked="false">Dark mode</div>
```

## Not reported

- Fallback lists where a valid role comes first (`role="switch checkbox"`): browsers use the first role they know.
- Roles from variables or template tags.

## Suppressing

```django
{# ramplint: ignore RL701 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL701 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL701"]
```
