# RL301 `heading-order`

Heading levels must not skip (e.g. <h2> followed by <h4>).

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)

## Why it matters

Many screen reader users navigate a page by its headings. A jump from `<h2>` to `<h4>` makes them think they missed a section. Pick heading levels for structure, and use CSS for size.

## What ramplint reports

- A heading more than one level deeper than the previous heading in the same template.

## Examples

Problems:

```django
{# ✗ #} <h2>Orders</h2>
{# ✗ #} <h4>Recent</h4>
```

Fixed:

```django
{# ✓ #} <h2>Orders</h2>
{# ✓ #} <h3>Recent</h3>
{# ✓ #} <h3>Recent</h3>
{# ✓ #} <h2>Archive</h2>
```

## Not reported

- The first heading of a template: child templates often start at `<h2>` because `base.html` owns the `<h1>`.
- Going back up any number of levels (`<h4>` followed by `<h2>`).

## Suppressing

```django
{# ramplint: ignore RL301 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL301 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL301"]
```
