# RL405 `form-label-empty`

Django form fields must not have an empty label.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)
- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

`label=""` is the usual way to make a "clean" form with placeholders only. Django then renders `<label for="id_email"></label>`: the label exists but is empty, so screen readers announce the field without a name, and the placeholder disappears as soon as the user types. This rule checks your `forms.py`, which no HTML linter looks at.

## What ramplint reports

In classes that inherit from a `...Form` class (`forms.Form`, `forms.ModelForm`, your own base forms):

- Fields with `label=""` or `label=_("")`.
- `labels = {"field": ""}` in a `ModelForm`'s `Meta`.
- `self.fields["field"].label = ""`, for example in `__init__`.

When the widget has a `placeholder`, the message says that a placeholder is not a label.

## Examples

Problems:

```python
from django import forms


class NewsletterForm(forms.Form):
    email = forms.EmailField(label="", widget=forms.EmailInput(attrs={"placeholder": "Your email"}))


class ProfileForm(forms.ModelForm):
    class Meta:
        labels = {"bio": ""}
```

Fixed:

```python
from django import forms
from django.utils.translation import gettext_lazy as _


class NewsletterForm(forms.Form):
    email = forms.EmailField(
        label=_("Email"), widget=forms.EmailInput(attrs={"placeholder": "you@example.com"})
    )
    search = forms.CharField(label="", widget=forms.TextInput(attrs={"aria-label": _("Search")}))
    next = forms.CharField(label="", widget=forms.HiddenInput)
```

To keep the design without a visible label, give the field a label and hide the `<label>` visually with CSS in the template.

## Not reported

- Fields whose widget has `aria-label`, `aria-labelledby` or `title` in its `attrs`.
- Hidden widgets (`HiddenInput`, `MultipleHiddenInput`).
- Labels from variables or function calls ramplint cannot read.

ramplint reads `forms.py` files and `forms/` packages of your project with `ast`; it never imports them.

## Suppressing

```python
# ramplint: ignore RL405
```

on the line with the problem or the line above it, or for the whole file:

```python
# ramplint: ignore-file RL405
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL405"]
```
