# RL406 `widget-id`

Custom Django widgets must keep the id that labels point to.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)
- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

Django connects a field's label to its widget through the id: `{{ field.label_tag }}` renders `<label for="id_rating">`, and errors and help text use `aria-describedby="id_rating_helptext"`. Django's own widget templates add the id with `{% include "django/forms/widgets/attrs.html" %}`. A custom widget whose template forgets `widget.attrs`, or that overrides `id_for_label()` to return nothing, silently breaks that link: the page looks fine, but the label points to nothing and screen readers announce the field without a name.

## What ramplint reports

In classes that inherit from a widget (`forms.Widget`, `TextInput`, `Select`, `RadioSelect`, ...):

- `id_for_label()` that always returns `None` or `""`.
- A `template_name` whose template renders form controls but never uses `widget.attrs` (or `attrs.html`). This check needs the project's template folders, so it runs when ramplint finds your Django project.

## Examples

Problems:

```python
from django import forms


class ColorPickerWidget(forms.TextInput):
    def id_for_label(self, id_, index=None):
        return None
```

Fixed:

```python
from django import forms


class ColorPickerWidget(forms.TextInput):
    template_name = "widgets/color_picker.html"
```

with the input in `widgets/color_picker.html` keeping the attributes:

```html
<input type="color" name="{{ widget.name }}"{% include "django/forms/widgets/attrs.html" %}>
```

## Not reported

- Widget templates that `{% extends %}` Django's templates, or render `widget.subwidgets`.
- `id_for_label()` that returns an id in some cases (like Django's `RadioSelect`, which points the label at the first option only when asked to).
- Templates that cannot be found, and `template_name` values ramplint cannot read.

## Suppressing

```python
# ramplint: ignore RL406
```

on the line with the problem or the line above it, or for the whole file:

```python
# ramplint: ignore-file RL406
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL406"]
```
