# RL402 `autocomplete-valid`

autocomplete must use valid autofill tokens.

## WCAG

- [1.3.5 Identify Input Purpose](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html) (level AA)

## Why it matters

Correct `autocomplete` values let browsers and password managers fill forms for people who find typing hard. A typo such as `emial` is silently ignored, so autofill just stops working.

## What ramplint reports

- `autocomplete` on `<input>`, `<select>` and `<textarea>` against the HTML grammar: `[section-*] [shipping|billing] [home|work|mobile|fax|pager] field [webauthn]`, or `on` / `off`. The message suggests the token you most likely meant: typos (`emial` → `email`) and common non-standard names (`zip` → `postal-code`, `phone` → `tel`, `first_name` → `given-name`).
- `<form autocomplete>`, which only accepts `on` and `off`.

## Examples

Problems:

```django
{# ✗ #} <input type="email" name="email" autocomplete="emial" aria-label="Email">
{# ✗ #} <input name="phone" autocomplete="mobile street-address" aria-label="Phone">
```

Fixed:

```django
{# ✓ #} <input name="email" autocomplete="email" aria-label="Email">
{# ✓ #} <input name="ship" autocomplete="section-gift shipping street-address" aria-label="Address">
{# ✓ #} <input name="promo" autocomplete="off" aria-label="Promo code">
```

## Not reported

- Values from variables or built with `{% if %}`.

## Suppressing

```django
{# ramplint: ignore RL402 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL402 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL402"]
```
