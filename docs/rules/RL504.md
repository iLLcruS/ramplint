# RL504 `anchor-is-valid`

Links must point somewhere; use <button> for actions.

## WCAG

- [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) (level A)
- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

Links navigate, buttons act. An `<a>` without `href` is not reachable with the Tab key, and a fake link (`href="#"`, `javascript:`) does not react to the Space key and is announced as a link that goes nowhere.

## What ramplint reports

- `<a href="#">` and `javascript:` links.
- `<a>` with an event handler (`onclick`, `onkeydown`, …) but no `href`.

## Examples

Problems:

```django
{# ✗ #} <a href="#" onclick="addToWishlist()">Add to wishlist</a>
{# ✗ #} <a href="javascript:void(0)">Open chat</a>
{# ✗ #} <a onclick="openMenu()">Menu</a>
```

Fixed:

```django
{# ✓ #} <button type="button" onclick="addToWishlist()">Add to wishlist</button>
{# ✓ #} <a href="#reviews">Jump to reviews</a>
```

## Not reported

- Real fragments (`#reviews`), `mailto:` links and URLs from `{% url %}` or variables.
- `<a name>` / `<a id>` anchors without event handlers.

## Suppressing

```django
{# ramplint: ignore RL504 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL504 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL504"]
```
