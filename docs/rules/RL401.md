# RL401 `form-label`

Form controls must have an associated <label>.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)
- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

A label tells users what to type, and clicking it focuses the field. A `placeholder` is not a label: it disappears as soon as the user starts typing and is often low contrast.

## What ramplint reports

- `<input>`, `<select>` and `<textarea>` without a `<label for>` that matches their `id`, a wrapping `<label>`, `aria-label`, `aria-labelledby` or `title`.

## Examples

Problems:

```django
{# ✗ #} <input type="email" name="email" placeholder="Email">
{# ✗ #} <select name="language"><option>English</option></select>
```

Fixed:

```django
{# ✓ #} <label for="email">Email</label> <input type="email" id="email" name="email">
{# ✓ #} <label>Email <input type="email" name="email"></label>
{# ✓ #} <input type="search" name="q" aria-label="Search orders">
```

## Not reported

- Hidden, submit, reset, button and image inputs.
- Widgets whose attributes are rendered dynamically (`<input {{ widget.attrs }}>`).
- Ids or `for` values built from variables, such as `{{ field.id_for_label }}`.

## Suppressing

```django
{# ramplint: ignore RL401 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL401 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL401"]
```
