# RL105 `object-alt`

<object> and <embed> must have a text alternative.

## WCAG

- [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) (level A)

## Why it matters

`<object>` and `<embed>` show PDFs, SVGs and plugin content that screen readers often cannot read. A text alternative tells users what the content is, and fallback content inside `<object>` (such as a download link) is also what users see when the browser cannot display it.

## What ramplint reports

- `<object>` without fallback text inside it, `aria-label`, `aria-labelledby` or `title`.
- `<embed>` without `aria-label`, `aria-labelledby` or `title` (it cannot have fallback content).

## Examples

Problems:

```django
{# ✗ #} <object data="{% static 'docs/prices.pdf' %}" type="application/pdf" width="600" height="800"></object>
{# ✗ #} <embed src="{% static 'docs/prices.pdf' %}" type="application/pdf">
```

Fixed:

```django
{# ✓ #} <object data="{% static 'docs/prices.pdf' %}" type="application/pdf" width="600" height="800"><a href="{% static 'docs/prices.pdf' %}">{% trans "Download the price list (PDF)" %}</a></object>
{# ✓ #} <embed src="{% static 'docs/prices.pdf' %}" type="application/pdf" title="{% trans 'Price list (PDF)' %}">
```

## Not reported

- Fallback text from variables, `{% trans %}` or `{% include %}`.
- Elements with `aria-hidden="true"`, `role="presentation"` / `role="none"` or dynamic attributes, and content of `<template>`.

## Suppressing

```django
{# ramplint: ignore RL105 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL105 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL105"]
```
