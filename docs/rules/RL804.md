# RL804 `focus-visible`

Keyboard focus must be visible.

## WCAG

- [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) (level AA)

## Why it matters

Keyboard users need to see where focus is, the way mouse users see the pointer. `outline: none` without another focus style leaves them guessing which link or button Enter will activate.

## What ramplint reports

This rule needs a rendered page: it runs in the browser scan
(`ramplint http://localhost:8000/` or `ramplint --runserver`) and is skipped
when ramplint lints templates.

- Elements that look exactly the same with and without keyboard focus. ramplint presses Tab through the page and compares, for every stop, the focus-related styles (outline, box-shadow, border, background, colour, underline) and, if those are equal, the pixels of the element.

## Examples

Problems:

```html
<style>button:focus { outline: none; }</style>
<button>Buy</button>
```

Fixed:

```html
<style>button:focus-visible { outline: 3px solid #1a73e8; outline-offset: 2px; }</style>
<button>Buy</button>
```

## Not reported

- Elements that keep the browser's default focus ring.
- Elements that change background, border, shadow or underline when focused.

## Suppressing

Put an HTML comment (it stays in the rendered page) on the line with the
element or the line above it:

```html
<!-- ramplint: ignore RL804 -->
```

or disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL804"]
```
