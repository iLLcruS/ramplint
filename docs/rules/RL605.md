# RL605 `meta-refresh`

Pages must not refresh or redirect after a delay.

## WCAG

- [2.2.1 Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) (level A)
- [3.2.5 Change on Request](https://www.w3.org/WAI/WCAG22/Understanding/change-on-request.html) (level AAA)

## Why it matters

A page that reloads or redirects on its own can move users away before they finish reading, and a reload puts screen reader users back at the top of the page. People who read slowly, use magnification or navigate by keyboard are hit first.

## What ramplint reports

- `<meta http-equiv="refresh">` with a delay greater than 0, both reloads (`content="30"`) and timed redirects (`content="5; url=..."`).

## Examples

Problems:

```django
{# ✗ #} <meta http-equiv="refresh" content="30">
{# ✗ #} <meta http-equiv="refresh" content="5; url={% url 'home' %}">
```

Fixed:

```django
{# ✓ #} <meta http-equiv="refresh" content="0; url={% url 'home' %}">
{# ✓ #} <p>{% trans "This page has moved." %} <a href="{% url 'home' %}">{% trans "Go to the new page" %}</a></p>
```

In a Django view, prefer `redirect()` over a timed redirect page.

## Not reported

- `content="0; url=..."`: an immediate redirect.
- Delays from variables or template tags.

## Suppressing

```django
{# ramplint: ignore RL605 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL605 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL605"]
```
