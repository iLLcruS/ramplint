# RL104 `svg-img-alt`

<svg role="img"> must have an accessible name.

## WCAG

- [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) (level A)

## Why it matters

`role="img"` tells screen readers that the SVG is a single meaningful image, but it is announced as just "image" unless it has a name. Inline SVGs have no `alt` attribute: the name comes from a `<title>` as the first child, `aria-label` or `aria-labelledby`.

## What ramplint reports

- `<svg role="img">` without a non-empty direct `<title>` child, `aria-label`, `aria-labelledby` or `title` attribute.

## Examples

Problems:

```django
{# ✗ #} <svg role="img" viewBox="0 0 24 24"><path d="M3 3h18v18H3z"/></svg>
{# ✗ #} <svg role="img"><title></title><use href="#icon-cart"></use></svg>
```

Fixed:

```django
{# ✓ #} <svg role="img" viewBox="0 0 24 24"><title>{% trans "Cart" %}</title><path d="M3 3h18v18H3z"/></svg>
{# ✓ #} <svg role="img" aria-label="{% trans 'Cart' %}"><use href="#icon-cart"></use></svg>
{# ✓ #} <svg aria-hidden="true"><use href="#icon-star"></use></svg>
```

Decorative icons next to visible text should be hidden with `aria-hidden="true"` instead.

## Not reported

- SVGs with `aria-hidden="true"` and SVGs without `role="img"`.
- SVGs whose content comes from `{% include %}` (for example an icon sprite partial), and SVGs with a dynamic `role` or dynamic attributes.

## Suppressing

```django
{# ramplint: ignore RL104 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL104 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL104"]
```
