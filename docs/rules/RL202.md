# RL202 `th-scope`

scope must be row, col, rowgroup or colgroup, and only used on <th>.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)

## Why it matters

`scope` tells screen readers which cells a header applies to, so a user moving through a row hears "Price, 20 euro". The attribute only accepts `row`, `col`, `rowgroup` and `colgroup`, and only works on `<th>`. A typo such as `scope="column"` is ignored, and `scope` on a `<td>` does not make it a header.

## What ramplint reports

- `scope` on `<th>` with any other value, with a "did you mean" suggestion (`column` → `col`).
- `scope` on `<td>`.

## Examples

Problems:

```django
{# ✗ #} <table><tr><th scope="column">{% trans "Name" %}</th><th scope="column">{% trans "Price" %}</th></tr></table>
{# ✗ #} <table><tr><td scope="row">{{ product.name }}</td><td>{{ product.price }}</td></tr></table>
```

Fixed:

```django
{# ✓ #} <table><tr><th scope="col">{% trans "Name" %}</th><th scope="col">{% trans "Price" %}</th></tr></table>
{# ✓ #} <table><tr><th scope="row">{{ product.name }}</th><td>{{ product.price }}</td></tr></table>
```

## Not reported

- Values from variables or template tags (`scope="{{ scope }}"`).
- Values in a different case (`scope="COL"`): HTML ignores the case.

## Suppressing

```django
{# ramplint: ignore RL202 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL202 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL202"]
```
