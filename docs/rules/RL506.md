# RL506 `duplicate-accesskey`

accesskey values must be unique within a template.

## WCAG

- Best practice, related to [2.1.4 Character Key Shortcuts](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html) (level A)

## Why it matters

`accesskey` gives an element a keyboard shortcut. When two elements share a key, browsers either activate the first one or only move focus between them, so the shortcut no longer does what its label promises. Access keys can also clash with screen reader and browser shortcuts, so use them sparingly.

## What ramplint reports

- The same `accesskey` (case does not matter) used on more than one element, pointing to the first use. The same key in `{% if %}` / `{% else %}` branches is fine.

## Examples

Problems:

```django
{# ✗ #} <a href="{% url 'search' %}" accesskey="s">{% trans "Search" %}</a> <button type="submit" accesskey="s">{% trans "Save" %}</button>
```

Fixed:

```django
{# ✓ #} <a href="{% url 'search' %}" accesskey="f">{% trans "Search" %}</a> <button type="submit" accesskey="s">{% trans "Save" %}</button>
{# ✓ #} {% if user.is_authenticated %}<a href="{% url 'account' %}" accesskey="a">{% trans "Account" %}</a>{% else %}<a href="{% url 'login' %}" accesskey="a">{% trans "Log in" %}</a>{% endif %}
```

## Not reported

- Keys from variables or template tags.
- Elements inside `<template>`.

## Suppressing

```django
{# ramplint: ignore RL506 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL506 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL506"]
```
