# RL604 `valid-lang`

lang values must be valid language tags.

## WCAG

- [3.1.1 Language of Page](https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html) (level A)
- [3.1.2 Language of Parts](https://www.w3.org/WAI/WCAG22/Understanding/language-of-parts.html) (level AA)

## Why it matters

Screen readers pick a voice from `lang`. They only understand [BCP 47](https://www.rfc-editor.org/info/bcp47) language tags such as `en`, `en-GB`, `ro` or `uk`. `lang="english"`, `lang="ua"` (the country code of Ukraine, not a language) or `lang="en_US"` are ignored, and the text is read with the wrong pronunciation rules.

## What ramplint reports

- `lang` and `xml:lang` values on any element that are not well-formed language tags, or whose language is not a known ISO 639 code. Country codes and language names get a suggestion: `ua` → `uk`, `cz` → `cs`, `english` → `en`, `en_US` → `en-US`.
- `lang` and `xml:lang` on the same element with different languages.

## Examples

Problems:

```django
{# ✗ #} <html lang="english">
{# ✗ #} <html lang="ua">
{# ✗ #} <p lang="en_US">Color</p>
{# ✗ #} <html lang="en" xml:lang="ro">
```

Fixed:

```django
{# ✓ #} <html lang="en">
{# ✓ #} <html lang="uk">
{# ✓ #} <p lang="en-US">Color</p>
{# ✓ #} <html lang="{{ LANGUAGE_CODE }}">
{# ✓ #} <span lang="zh-Hant">繁體中文</span>
```

## Not reported

- `{{ LANGUAGE_CODE }}` and other dynamic values.
- Empty `lang=""` (it means "unknown language"); a missing page language is reported by [RL601](RL601.md).
- Private-use and grandfathered tags such as `x-klingon` and `i-klingon`.
- Three-letter language codes (`haw`, `fil`) are accepted without checking the registry.

## Suppressing

```django
{# ramplint: ignore RL604 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL604 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL604"]
```
