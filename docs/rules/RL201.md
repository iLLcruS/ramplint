# RL201 `table-header`

Data tables must use <th> header cells.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)

## Why it matters

Header cells tell screen readers what each data cell means: a user moving through a row hears "Price, 20 euro" instead of just "20 euro". Bold text or `role="columnheader"` on a `<td>` does not create that relationship reliably; a real `<th>` does.

## What ramplint reports

- `<table>` that contains no `<th>` (nested tables are checked on their own).

## Examples

Problems:

```django
{# ✗ #} <table><tr><td>Name</td><td>Price</td></tr><tr><td>{{ p.name }}</td><td>{{ p.price }}</td></tr></table>
```

Fixed:

```django
{# ✓ #} <table><tr><th scope="col">Name</th><th scope="col">Price</th></tr><tr><td>{{ p.name }}</td><td>{{ p.price }}</td></tr></table>
{# ✓ #} <table role="presentation"><tr><td>{{ sidebar }}</td><td>{{ content }}</td></tr></table>
```

## Not reported

- Layout tables marked with `role="presentation"` or `role="none"`.
- Tables whose rows come from `{% include %}`, `{% block %}` or `{{ form.as_table }}`: the headers may be rendered there.

## Suppressing

```django
{# ramplint: ignore RL201 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL201 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL201"]
```
