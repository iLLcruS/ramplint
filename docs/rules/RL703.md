# RL703 `aria-valid-attr-value`

ARIA attribute values must match the attribute's type.

## WCAG

- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

ARIA attributes only accept specific values. `aria-hidden="yes"` is ignored, so the content is not hidden; `aria-checked="checked"` leaves a checkbox without a state; an `aria-labelledby` that points to a missing id gives the element no name.

## What ramplint reports

- true/false attributes with other values (`aria-hidden="yes"`, `aria-disabled="1"`).
- Token attributes with unknown values (`aria-live="loud"`, `aria-current="active"`, `aria-checked="checked"`).
- Integer and number attributes with invalid values (`aria-level="0"`, `aria-valuenow="high"`).
- Empty id references, and `aria-labelledby` / `aria-describedby` that reference ids missing from the template.

## Examples

Problems:

```django
{# ✗ #} <div class="backdrop" aria-hidden="yes"></div>
{# ✗ #} <div role="status" aria-live="loud">{{ message }}</div>
{# ✗ #} <div role="dialog" aria-labelledby="dialog-title">…</div>
```

Fixed:

```django
{# ✓ #} <div class="backdrop" aria-hidden="true"></div>
{# ✓ #} <div role="status" aria-live="polite">{{ message }}</div>
{# ✓ #} <div role="dialog" aria-labelledby="dialog-title"><h2 id="dialog-title">Filters</h2></div>
```

## Not reported

- Values from variables or template tags.
- Missing-id checks in templates that use `{% include %}`, `{% block %}`, dynamic ids or dynamic attributes, because the target may be rendered elsewhere.

## Suppressing

```django
{# ramplint: ignore RL703 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL703 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL703"]
```
