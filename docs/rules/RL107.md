# RL107 `image-redundant-alt`

Image alt text must describe the image, not repeat a file name or nearby text.

## WCAG

- [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) (level A)

## Why it matters

Screen readers already say "image" before the alt text, so `alt="Image of a cat"` is read as "image, image of a cat". A file name such as `IMG_2031.jpg` tells nothing about the picture. An image inside a link or button whose alt repeats the visible text makes screen readers announce the same words twice.

## What ramplint reports

- `alt` that is a file name (`photo.jpg`, `IMG_2031.png`).
- `alt` that is only a placeholder word: `image`, `picture`, `photo`, `graphic`, `icon`, `spacer`.
- `alt` that starts with "image of", "picture of", "photo of" or "graphic of".
- An `<img>` inside `<a>` or `<button>` whose `alt` is the same as the rest of the text.

## Examples

Problems:

```django
{# ✗ #} <img src="{{ user.avatar.url }}" alt="avatar.png">
{# ✗ #} <img src="cat.jpg" alt="Picture of a cat on a sofa">
{# ✗ #} <a href="{% url 'cart' %}"><img src="cart.svg" alt="Cart"> Cart</a>
```

Fixed:

```django
{# ✓ #} <img src="{{ user.avatar.url }}" alt="{{ user.get_full_name }}">
{# ✓ #} <img src="cat.jpg" alt="A cat asleep on a sofa">
{# ✓ #} <a href="{% url 'cart' %}"><img src="cart.svg" alt=""> Cart</a>
```

## Not reported

- `alt=""` (decorative images) and `alt` built by the template (`alt="{{ name }}"`).
- Links and buttons whose text is only known at render time.

## Suppressing

```django
{# ramplint: ignore RL107 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL107 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL107"]
```
