# RL404 `field-label`

Form fields rendered one by one must have their label.

## WCAG

- [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) (level A)
- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

In Django templates, `{{ field }}` and `{{ form.email }}` render **only the widget**: the `<input>`, without its `<label>`. `{{ form }}`, `{{ form.as_p }}`, `{{ form.as_div }}` and `{{ field.as_field_group }}` render the label, but once a template lays fields out by hand, the label is easy to forget. The form looks fine to sighted users (there is a placeholder or text next to it), while screen readers announce "edit text" with no name. The same happens with django-widget-tweaks: `{% render_field form.email class="input" %}` and `{{ form.email|add_class:"input" }}` render the widget alone.

## What ramplint reports

- `{{ field }}` inside `{% for field in form %}` (or `form.visible_fields`), `{{ form.email }}`, `{{ form.email|add_class:"..." }}` and `{% render_field form.email %}`, when the template has no label for that field: `{{ field.label_tag }}`, `<label for="{{ field.id_for_label }}">`, `<label for="id_email">`, or a `<label>` around the field.

## Examples

Problems:

```django
{# ✗ #} {% for field in form %}<div class="field">{{ field }}{{ field.errors }}</div>{% endfor %}
{# ✗ #} <span>{% trans "Email" %}</span> {{ form.email }}
{# ✗ #} {% load widget_tweaks %}{% render_field form.email class="input" placeholder="Email" %}
```

Fixed:

```django
{# ✓ #} {% for field in form %}<div class="field">{{ field.label_tag }} {{ field }}{{ field.errors }}</div>{% endfor %}
{# ✓ #} <label for="{{ form.email.id_for_label }}">{% trans "Email" %}</label> {{ form.email }}
{# ✓ #} {% load widget_tweaks %}<label for="{{ form.phone.id_for_label }}">{% trans "Phone" %}</label> {% render_field form.phone class="input" %}
{# ✓ #} {% for field in form %}{{ field.as_field_group }}{% endfor %}
{# ✓ #} {{ form.as_div }}
```

To hide a label visually but keep it for screen readers, use a "visually hidden" CSS class on the `<label>`, not `display: none`.

## Not reported

- `{{ form }}`, `{{ form.as_p }}`, `{{ form.as_div }}`, `{{ field.as_field_group }}`, `|as_crispy_field` and other filters that render the label.
- Hidden fields: `{% for field in form.hidden_fields %}`, templates that check `{% if field.is_hidden %}`, and fields named `next`, `id`, `token`, `*_id`.
- `{% render_field ... aria-label="..." %}`.
- Fields inside `display: none` / `hidden` containers, inside headings and links (that is text, not a control), and inside attribute values.
- `{{ field }}` that is not known to be a form field (a loop over something else, or a variable passed to an `{% include %}`).

ramplint cannot see the form class from the template, so a form attribute that is not a field (for example `{{ form.title }}` used as text) can be reported; suppress it inline.

## Suppressing

```django
{# ramplint: ignore RL404 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL404 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL404"]
```
