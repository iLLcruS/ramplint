# RL704 `aria-required-attr`

Elements with a role must have the ARIA attributes that role requires.

## WCAG

- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

Some roles describe widgets with a state. A `role="switch"` without `aria-checked` is announced as "switch" with no on/off state, and a `role="heading"` without `aria-level` has no level in the headings list.

## What ramplint reports

- `checkbox`, `radio`, `switch`, `menuitemcheckbox`, `menuitemradio` without `aria-checked`.
- `combobox` without `aria-expanded`.
- `heading` without `aria-level`.
- `slider` without `aria-valuenow`, `scrollbar` without `aria-controls` and `aria-valuenow`.

## Examples

Problems:

```django
{# ✗ #} <div role="switch" tabindex="0">Dark mode</div>
{# ✗ #} <div role="heading">Orders</div>
```

Fixed:

```django
{# ✓ #} <div role="switch" tabindex="0" aria-checked="false">Dark mode</div>
{# ✓ #} <div role="heading" aria-level="2">Orders</div>
{# ✓ #} <input type="checkbox" role="switch" id="dark"> <label for="dark">Dark mode</label>
```

## Not reported

- Native elements that provide the state themselves (`<input type="checkbox" role="switch">`, `<h2 role="heading">`, `<select role="combobox">`).
- Elements with dynamic attributes.

## Suppressing

```django
{# ramplint: ignore RL704 #}
```

on the line with the problem or the line above it, or for the whole file:

```django
{# ramplint: ignore-file RL704 #}
```

You can also disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL704"]
```
