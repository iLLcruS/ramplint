# RL807 `expanded-state`

A control that opens content must set aria-expanded="true" when it does.

## WCAG

- [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) (level A)

## Why it matters

A button with `aria-expanded="false"` tells screen reader users that something is collapsed. If the button opens the menu but the attribute stays `false`, they are told the menu is closed while it is open.

## What ramplint reports

This rule needs a rendered page: it runs in the browser scan
(`ramplint http://localhost:8000/` or `ramplint --runserver`) and is skipped
when ramplint lints templates.

- A control with `aria-expanded="false"` that, when ramplint clicks it, shows new content but keeps `aria-expanded="false"`.

## Examples

Problems:

```html
<button aria-expanded="false" aria-controls="menu">Menu</button>
<script>button.onclick = () => { menu.hidden = !menu.hidden; };</script>
```

Fixed:

```html
<button aria-expanded="false" aria-controls="menu">Menu</button>
<script>button.onclick = () => { menu.hidden = !menu.hidden; button.setAttribute("aria-expanded", String(!menu.hidden)); };</script>
```

## Not reported

- Controls that do not open anything when clicked.

## Suppressing

Put an HTML comment (it stays in the rendered page) on the line with the
element or the line above it:

```html
<!-- ramplint: ignore RL807 -->
```

or disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL807"]
```
