# RL805 `focus-obscured`

A focused element must not be hidden behind sticky or fixed content.

## WCAG

- [2.4.11 Focus Not Obscured (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) (level AA)

## Why it matters

A sticky header, a fixed footer or a cookie banner can cover the element that has keyboard focus. The user presses Tab and focus disappears behind the banner.

## What ramplint reports

This rule needs a rendered page: it runs in the browser scan
(`ramplint http://localhost:8000/` or `ramplint --runserver`) and is skipped
when ramplint lints templates.

- An element that is completely covered by a `position: fixed` or `position: sticky` element when it has keyboard focus. The message names the covering element.

## Examples

Problems:

```html
<div style="position: fixed; bottom: 0; height: 120px">We use cookies.</div>
<a href="/terms/" style="position: absolute; top: 720px">Terms</a>
```

Fixed:

```html
<style>html { scroll-padding-bottom: 130px; }</style>
<div style="position: fixed; bottom: 0; height: 120px">We use cookies.</div>
```

## Not reported

- Elements that are only partly covered (WCAG 2.4.12 at level AAA asks for that).

## Suppressing

Put an HTML comment (it stays in the rendered page) on the line with the
element or the line above it:

```html
<!-- ramplint: ignore RL805 -->
```

or disable the rule in `pyproject.toml`:

```toml
[tool.ramplint]
ignore = ["RL805"]
```
